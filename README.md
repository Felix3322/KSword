# KSword 实验功能分支

本分支用于保存尚未合并到 KSword 主仓库 `main` 分支的研究性功能与配套集成。它不是完整功能总览，也不表示下列实现均已达到生产可用状态。

- 主仓库主线：`KSwordDEV/KSword:main`
- 当前实验分支：`Felix3322/KSword:codex/experimental-tooling`
- 本文档对比基点：主线提交 `6943a1a3`
- 本次实验分支快照：`ea1b8ea8`

> [!CAUTION]
> 本分支包含能够绕过常规操作系统保护边界的内核、虚拟化、存储控制器和原始文件系统操作。错误使用可能造成系统崩溃、不可启动、数据永久丢失或硬件状态异常。仅应在隔离研究环境、虚拟机快照或可丢弃介质上评估；不要对生产设备、系统盘、启动盘或仍挂载的卷执行写入操作。

## 尚未进入主线的功能

### 1. 独立存储控制器研究栈

这一组功能提供独立的 R3 客户端、研究界面和 `KswordARKControllerDriver` 驱动，用于在受控会话中研究 AHCI、NVMe 与传统 IDE 控制器。

主要能力包括：

- 枚举控制器、端口、命名空间与设备身份信息，并生成审计记录。
- 管理控制器所有权、研究会话、命令队列和数据缓冲区。
- 发送受约束的原始控制器命令。
- 对读、写、刷新和回读结果进行校验。
- 写入前检查预期哈希，并在失败时尝试事务回滚。
- 在明确条件下执行受控 NVMe 控制器复位。

应用场景主要是存储协议研究、控制器行为验证、故障分析和隔离设备的数据恢复实验。该路径可能绕过 Windows 存储栈，风险极高；写入功能只适合无挂载卷、非系统盘且能够承受完全损坏的设备。

### 2. 常驻 HVM / VMX 研究栈

该实现提供多处理器 VMX 生命周期管理及失败回滚框架，并包含：

- EPT 构建、规则管理和访问陷阱。
- 根据 MTRR 选择 EPT 内存类型。
- fail-closed、单次放行、MTF 与 INVEPT 协作路径。
- VM-exit、EPT、生命周期和严重错误事件环形缓冲区。
- 用户态状态查看、控制和诊断接口。

应用场景包括内核行为观测、页级访问研究、虚拟化安全实验和底层故障诊断。它可能与 Hyper-V、VBS、其他虚拟机监控器或平台固件策略冲突，错误配置可能直接导致宿主机崩溃。

### 3. Nested VMX、Nested EPT 与 eVMCS

分支中保留了嵌套虚拟化相关的数据结构、能力探测和部分执行路径，包括嵌套 VMCS、嵌套 EPT 以及 Hyper-V eVMCS 兼容研究。

目前它属于研究性、部分实现：

- 尚未完成完整的 `vmcs02` 合成。
- 尚未覆盖全部 VM-exit 反射语义。
- 尚未形成完整的 Shadow EPT 与稳定 L2 运行路径。

因此，这部分适合能力验证、接口研究和后续实现基础，不应被视为可直接承载通用 L2 虚拟机的完整嵌套虚拟化方案。

### 4. 深层原始 Windows 文件系统分析

该分支扩展了绕过常规文件 API 的磁盘与文件系统分析能力：

- NTFS 属性列表、扩展文件记录、命名数据流和区段一致性检查。
- FAT12、FAT16、FAT32 簇链与长文件名解析。
- exFAT 元数据和簇链解析。
- 有边界限制的 ReFS 结构解析。
- 原始目录浏览、文件区段检查与导出。
- 在能够证明目标区段精确、当前空闲且卷处于离线状态时，提供受限的删除数据清理路径。

其主要用途是离线取证、损坏文件系统诊断、数据布局验证和恢复研究。原始读取也可能因格式误判产生错误结论；任何擦除或写入操作都具有永久数据损失风险。

### 5. 基于精确身份的 IDT / PDB 基线比较

主线已经具备通用的可信已加载映像基线；本分支额外加入了与映像 SHA-256、PDB GUID/Age 等精确身份绑定的预期 IDT 处理例程候选，并在描述符表界面中比较观测地址与预期结果。

应用场景包括：

- 检查 IDT 处理例程是否落在预期内核映像和符号身份范围内。
- 辅助定位未知重定向、版本不匹配或符号配置错误。
- 为内核完整性调查提供更具体的证据线索。

比较差异不等同于恶意修改。虚拟化平台、安全产品、调试器和系统版本差异都可能产生合法变化，结果必须结合当前机器环境人工判断。

### 6. 重复危险确认的持久化抑制策略

本分支允许用户持久化选择，跳过部分重复出现的界面级危险操作确认框。它只改变交互策略，不会关闭底层的目标范围限制、写入前状态校验、事务验证、回读、回滚、审计记录或驱动授权检查。

该功能适用于隔离实验环境中的重复操作和自动化研究，但会减少阻止误操作的最后一道人工确认。启用前必须理解对应操作的真实影响，并确保底层保护条件仍然有效。

## 配套但不单独构成功能的改动

为了支撑上述功能，本分支还包含：

- 解决方案、项目文件和筛选器集成。
- 独立控制器驱动的 CI 配置。
- HVM 与存储控制器共享 IOCTL 协议。
- IOCTL 审计规则。
- PDB 配置生成与发布同步所需的 IDT 元数据。
- 双语界面文本和相关设计文档。

这些内容属于实现、构建或发布支撑，不应被单独解读为新的用户功能。

## 已进入主线，不属于本分支剩余功能

以下能力已经合并到主仓库 `main`，因此不作为保留本实验分支的理由：

- 原始 PE 分析与反汇编。
- 内核地址指令视图。
- 任意小范围内核字节事务。
- 通用可信已加载映像基线。
- 运行时精确 PDB DynData 回退。

## 后续合并前检查

分支差异会随主线和实验分支继续变化。准备评审或合并前，应重新获取远端状态并以实际差异为准：

```powershell
git fetch origin main
git fetch ob codex/experimental-tooling
git diff --stat origin/main...ob/codex/experimental-tooling
git diff --name-status origin/main...ob/codex/experimental-tooling
```

高风险功能应按独立边界评审，并在隔离 CI 和专用测试环境中验证后再考虑进入主线；不要仅依据本 README 直接执行整分支合并。
